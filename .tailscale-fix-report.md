# Tailscale --set-path prefix-stripping fix — report

**Date:** 2026-07-12
**Branch:** `fix/tailscale-path-strip`

## Bug

`tailscale serve --set-path /<name> <port>` **strips** the `/<name>` prefix before proxying to the
container — confirmed empirically on Bos-Desktop. The demo-tools fastapi starter, template
Dockerfile, and the local-Tailscale-target design spec all assumed the opposite ("Tailscale
forwards the path without stripping it"), which breaks every locally-deployed app two ways:

1. uvicorn without `--proxy-headers` doesn't see `X-Forwarded-Proto: https`, so `url_for()` /
   redirects emit `http://` absolute URLs — browsers block these as mixed content on the
   `https://` page (localhost masks this, since the `http://` URL is directly reachable there).
2. A `StaticFiles` Mount only matches the full `/<name>/static/...` path; once the prefix is
   stripped, the incoming request is a bare `/static/...` that the Mount 404s on. Normal routes
   are unaffected because Starlette's `get_route_path()` only strips `root_path` from paths that
   actually carry it.

## Fix

1. **`src/demo_tools/_data/starters/fastapi/main.py`** — corrected the header comment (strips, not
   forwards-unstripped); kept `root_path=os.getenv("ROOT_PATH", "")` for URL generation only;
   replaced the previously-recommended `StaticFiles` Mount pattern with a documented route-based
   static handler (`@app.get("/static/{path:path}", name="static")` → `FileResponse`, with a
   path-traversal guard resolving against `STATIC_DIR`).
2. **`src/demo_tools/_data/template/Dockerfile.jinja`** — the `fastapi` stack's uvicorn `CMD` now
   includes `--proxy-headers --forwarded-allow-ips=*`, with a comment explaining why (trusts the
   proxy's `X-Forwarded-Proto`; only the local proxy reaches the container so trusting all
   forwarded IPs is safe).
3. **`src/demo_tools/_data/starters/nextjs-fastapi/api/Dockerfile`** (static, not `.jinja`) — same
   `--proxy-headers --forwarded-allow-ips=*` addition to its uvicorn `CMD`, since it's also
   uvicorn-based and reachable via the local target.
4. **`docs/superpowers/specs/2026-07-10-local-tailscale-deploy-target-design.md`** — corrected
   every "Tailscale does NOT strip / forwards unstripped" claim (top status banner, §1 runtime
   facts, the architecture diagram, §4.3, the `tailscale_path` Copier question help text, §5.2, and
   §12 assumptions), and rewrote §5.4 to explain: routing needs no change (Starlette's
   `get_route_path()` is conditional on the incoming path carrying the prefix), but URL
   *generation* still needs `root_path` plus uvicorn `--proxy-headers`, and static assets must be
   served via a route, not a Mount.
5. **`tests/test_local_target.py`** — updated `test_fastapi_root_path_routing_across_targets`'s
   docstring/assertions to test the realistic stripped-prefix request (`/healthz`, not
   `/tmp-demo/healthz`) in addition to the full-prefix one; added
   `test_fastapi_starter_serves_static_via_route_not_mount` covering the new static route (asset
   serving, path-traversal guard, `url_for` output, and that no `StaticFiles` Mount is used in
   actual code).

## Verification

- `uv run pytest -q` → **132 passed** (131 pre-existing + 1 new), no expectation changes were
  needed for existing tests — none of them asserted the specific "unstripped"/Mount behaviour, only
  the new test I added does.
- Manual copier-render sanity check: scaffolded a throwaway `fastapi --target local` project,
  confirmed the rendered `Dockerfile` CMD carries the new flags and `app/main.py` matches the
  starter.
- Manual smoke test with `fastapi.testclient.TestClient` against the rendered starter: `/`,
  `/healthz`, and `/static/app.css` (with a real asset dropped in) all return 200; a path-traversal
  attempt (`/static/../main.py`) returns 404; `url_for("static", path="app.css")` emits
  `/static/app.css` as expected.
